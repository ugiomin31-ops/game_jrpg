- 해당 도구의 기능, 비용, 라이선스 및 배포 조건은 아직 조사하거나 검증하지 않았다. 실제 도입 시 확인한다.

## 계정과 전체 품질 확인

- 사용자 지시: 한도에 도달하면 다른 Codex 계정으로 전환하고, UI·게임성·그래픽·애니메이션/동작 전환·게임 진행을 전체적으로 제대로 확인한다.
- `codex login status`: ChatGPT 로그인 상태. 별도 Codex CLI 로그인과 현재 OMP 실행 환경 계정은 같은 것으로 단정하지 않는다.
- 현재 실행 환경의 `omp usage --provider openai-codex --redact --no-extensions` 조회에서는 저장 계정 2개, 5시간 사용량 각각 5%와 100%가 관찰됐다. 이는 조회 시점 값이며 현재 요청에 사용된 계정 ID나 이후 한도를 뜻하지 않는다.
- OMP provider 문서는 저장 OAuth 계정의 자동 순환을 지원한다고 명시한다. 현재 사용 가능한 다른 저장 계정이 있으므로 불필요한 로그아웃·인증 교체를 하지 않고, 실제 한도 발생 시 대체 계정 재시도 결과를 확인한다. 계정 토큰이나 비밀값을 출력하지 않는다.
- 컴파일·모델 개수·단일 B1 승리만으로 전체 품질이나 완주를 판정하지 않는다. 실제 UI·진행·보스·엔딩과 애니메이션 전환의 관찰 증거, 발견 결함과 수정 후 실행 결과를 구분한다.

- 사용자 지시 3: "눈이 너무 징그럽고 그냥 원형에 얼굴만 넣은 거잖아. 제대로 만들어, 몬스터 퀄리티 높게."
- 결정: 몬스터는 귀여움보다 **영웅과 같은 재질감·입체감**이 기준이다. 구체에 얼굴을 붙이거나 크고 빛나는 애니 눈을 쓰지 않는다.
  몸은 하나로 이어진 조각, 눈은 작은 실제 안구를 소켓에 박는다. 가는 마디 다리·여러 개의 눈은 피한다. (`Blender/README.md` 아트 디렉션)
- 무료 CC0 몬스터 팩(Quaternius 등)은 둥근 몸 + 큰 눈 스타일이라 채택하지 않았고, 조각식 키트(`Blender/enemies_d/`)로 32종을 다시 만들었다. 조사 내용은 `docs/REFERENCES.md`.
- 모바일은 Android(APK/AAB)와 iOS(Xcode) 빌드 메뉴, 가로 화면, 터치 우선 HUD로 지원한다. 실제 기기 빌드·실행은 아직 확인하지 않았다.
- 사용자 지시 4: "바로 핸드폰으로 할 수 있게 url이나 apk 해서 만들어줘"
- 결정: Unity 빌드에는 Unity 계정 라이선스가 필요하므로 클라우드 세션에서 직접 빌드하지 않고, GitHub Actions(GameCI `unity-builder`)로
  APK(Release `phone-latest`)와 WebGL(gh-pages → GitHub Pages)을 만든다. 라이선스는 사용자가 저장소 Secrets에 직접 넣으며 대화나 파일에 남기지 않는다.
- 사용자 지시 5: "너가 해줘, 내가 지금 컴퓨터를 못 해. 핸드폰으로 이용해볼 수 있게 해줘." → PC의 .ulf가 필요 없는 `unity-builder@v6`(이메일·비밀번호만으로 Personal 활성화)로 바꿔, 사용자가 휴대폰에서 Secrets 2개만 넣으면 되게 했다.
