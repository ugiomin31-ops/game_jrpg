Three frames do not guarantee that interval. `UIButton.Click` also has its own 0.25-second repeated-click limit. No production input or transaction guard was changed. The old failed run did not record its click timestamp, so its exact timing cannot be reconstructed and stale UI input was not independently established.

The fixture now reads the existing modal/button deadlines, waits for both, verifies the same live top modal/button, and calls the real button once when accepted. It never overwrites private guard fields, calls `Answer` directly, or invokes the transaction service to force success. It records modal-open time, deadlines, answered state, actual quantity and gold. Narrow scope additionally clicks immediately after creation to exercise the real rejection path.
